# Claude Code skills for M9

Two skills for [Claude Code](https://claude.com/claude-code), the ones
the M9 repository itself works with:

- `m9/` -- what a Pascal, Oberon or Modula-2 hand gets wrong in M9,
  as a short ordered list, each item pointing at the gated document
  that settles it (the report, `docs/modules/`, `probes/`, `museum/`,
  the tutorial).  Loaded whenever a `.m9` file is written, changed or
  diagnosed.
- `m9-lookup/` -- how to find what already exists before writing it:
  the compiler's own `m9c --json` for a module's exact signatures,
  modes and RAISES sets, never a remembered list of names.

## Using them

Copy both directories into your project's `.claude/skills/`:

    cp -R skills/m9 skills/m9-lookup  YOURPROJECT/.claude/skills/

Claude Code lists project skills from that directory and loads one
when its description matches the work at hand; a skill can also be
asked for by name (`/m9`).

## What they are not

They restate no part of the language and carry no list of library
names -- a copy of either drifts within a day, as one did.  Every
pointer goes to something a gate holds true: the report is normative,
`docs/modules/` is generated by the compiler and checked byte for
byte, every probe is refused with the diagnostic on its first line,
every museum piece fails to compile, and every tutorial example runs
and prints what the page says.  When a skill and one of those
disagree, the gated one is right, and the skill is what gets fixed.

These two files are the source; the repository's own `.claude/skills/`
entries point here.
