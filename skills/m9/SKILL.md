# M9: what fluency gets wrong

M9 is Wirth-family and READS like Modula-2, which is the trap: the
hand writes what it knows and the checker refuses it.  This is the
list, ordered by how often one real session hit each item (a port of
a 45,000-line Fortran model, ten modules, ~3,000 lines, measured
before the skill was written).  Everything here is a pointer into a
GATED asset -- the tutorial (github.com/atverm/M9Tutorial, live at
tutorial.modula9.net) is run by its gate, `docs/modules/` is
regenerated by the compiler and compared byte for byte, every probe
in `probes/` is refused with the diagnostic on its first line -- so
when this file and one of them disagree, the gated one is right.

**Process rule, before the language**: write `.m9`, `.c`, `.f90` and
`.py` files with the file tool.  Never through a heredoc or a Python
string literal -- 86 of one session's C-compiler errors were escape
sequences mangled by a quoting layer, and none were in files the file
tool wrote.

**Never `pkill -f` a pattern; kill the PID you started, or
`fuser -k PORT/tcp`.**  A pattern kill matches ANY process whose
command line carries the text: another session's server, a test
harness's own wrapper -- and on Windows it is wrong almost every
time, because the `wsl.exe` wrapper's command line carries the whole
command including the pattern, so the kill matches the wrapper (or
the session) itself.  This has fired at least five separate times
across the project's sessions (three self-kills, then a gate's
cleanup sweep repeatedly killing a BYSTANDER session's reference
server).  Record the `$!` of every background process you start and
kill that; for a server, `fuser -k <port>/tcp` kills exactly the
process holding the port and nothing else.

**A helper script is an M9 script, not a Python one** (Alex,
2026-10-04).  When a project needs a tool -- cut a fixture, convert a
file, regenerate a table -- write it as an M9 program whose first
line is `#!/usr/bin/env -S m9c --run`, mark it executable, and run it
by name: `m9c --run` (0.15 on) compiles it into a cache the first
time, about two seconds, and runs the cached program after that, in
milliseconds (`m9c --help`, report par 2 for the `#!` line, gate
`runtime/test/run.sh`).  Name the file like its module, letters and
digits only: `--run` names its generated C after the FILE, and a
hyphen in it made an invalid header guard (m9c 0.15.0-dev).  Before
deleting the Python a script replaces, run both on the same input
and compare the outputs byte for byte (the first port, a fixture
cutter, wrote the same eight files as its Python before the Python
went).  **Keep the Python that IS an
oracle** -- numpy, scipy, a reference implementation's own code: a
reference rewritten in M9 holds M9 to itself, and a test that cannot
disagree is not evidence.

## The list

1. **An IMPLEMENTATION MODULE has its own IMPORT list.**  The
   DEFINITION's imports do not carry over.  `unknown procedure:
   Math.Log` with Math.Log plainly existing means THIS module did not
   import Math.  This was the single largest class in the baseline --
   8 of 9 "unknown" names existed.  Pattern: `corpus/Mat.m9`
   (the definition imports nothing; the implementation adds Math).

2. **Look the name up before calling it -- by asking the compiler.**
   `m9c --json M.m9` writes `M.json`: every exported name with its
   parameters, modes, result and RAISES, as data; `docs/modules/M.md`
   is the same document as a page.  Neither this skill nor
   `m9-lookup` carries a list of names, because a list copied into a
   prompt was wrong within a day (`Io.ListDir`).  (The negative
   knowledge this item used to carry -- "Math has NO integer
   abs/min/max" -- expired on 2026-09-27: `Math.AbsI64/MinI64/MaxI64/
   ClampI64` and `Min/Max/Clamp` exist, and so do `Sort.F64s/I64s/
   Strs/ArgF64/By` and `Text.Keep/Cat/Fields`.  Ask the compiler.)
   See the `m9-lookup` skill for the query.  One lexical trap: `(*`
   opens a comment ANYWHERE, comments nest, so `(*Name)` inside a
   comment or a string of C text opens one that never closes -- write
   `( *` or say it in words.

3. **`#` is not-equal.**  `<>` is a parse error, and a parse error
   cascades -- one `<>` gave *981 parse errors*.  m9c prints the first
   eight as `FILE:LINE:COL: parse: MSG`; the first one is the real
   one, the rest are the resynchronisation.  (Report par 10.)

4. **RAISES is proved complete, so it is transitive.**  Whatever you
   call joins your set: `Math.Sqrt` adds `ValueRange`, `Exp`/`Pow`
   add `Overflow`, every `I64 (x)` / `F32 (x)` conversion adds
   `ValueRange`, every index adds `IndexError`.  The definition and
   the implementation heading must agree to the letter (probe
   `signature-differs-from-definition`).  Par 5; tutorial 3.

5. **Strings have no escapes.**  `'it''s'` is NOT an apostrophe: the
   second quote ENDS the string.  Use the other delimiter: `"it's"`.
   `+` concatenates two STRINGS into HEAP, and a CHAR joins as one
   code point on either side (`s + c`, `c + s`; since 2026-09-06);
   a NUMBER never does -- `Fmt.I64Str` it first.  Par 2; tutorial
   2 and 12.

6. **Build a string with `+` and a CASE that ANSWERS one.**  `+`
   concatenates into `HEAP` (par 2.3) and works on every operand
   shape that has a type -- locals, literals, CONSTs, call results,
   record fields, slice and array elements, chains.  So a mapping
   from a code to a string is a procedure that RETURNS one:

       PROCEDURE Reason (status: I64) : STR =
       BEGIN
         CASE status OF
         | 200 : RETURN 'OK'
         | 404 : RETURN 'Not Found'
         ELSE    RETURN 'Internal Server Error'
         END
       END Reason ;

       DynStr.Append (scratch, d, 'HTTP/1.1 '
                      + Fmt.I64Str (status) + ' '
                      + Reason (status)) ;

   **The number appears ONCE, in the label.**  Writing `| 200 :
   RETURN '200 OK'` says it twice, and the two can disagree -- an arm
   labelled 200 returning `'201 OK'` compiles perfectly happily.
   Format it from the value instead.

   **NOT** a chain of `IF status = 200 THEN DynStr.Append (...)
   ELSIF ...`, which is what an earlier session wrote in a server:
   34 lines, one Append per status, and a reviewer has to read every
   branch to learn there is no logic in any of them.  The CASE reads
   as the table it is.  A real table -- `SLICE OF RECORD code, text
   END` filled once and searched -- is also fine and is better when
   the rows come from data.  DynStr is for ACCUMULATING in a loop;
   `+` is for composing an expression, and this language's reason
   for existing is the reviewer.

7. **No NIL.**  `OPT PTR T`, and the only way in is `IF x IS SOME p
   THEN ... END` -- as the WHOLE condition of IF/ELSIF/WHILE, binding
   `p`.  `NONE` is the absent value.  OPT is traced through fields
   (`r.f IS SOME p`).  A cross-module `PTR T IN pool` can type as
   UNKNOWN and then `IS SOME` on it is silently accepted by the
   checker and refused by the generator -- read the declaration.
   Par 2.2; probes `is-some-on-non-opt`, `opt-through-field`;
   exemplar `corpus/Json.m9`.

8. **No implicit conversion, none, widening included.**  `I64 (i32)`,
   `F64 (f32)`, `Kind.FlexFloat (x)`; each RAISES ValueRange.  An
   integer literal adapts to any integer type and must FIT it (`s :=
   40000` for an I16 is refused by name since 2026-09-27; before that
   it stored -25536); a `<real>` literal adapts
   to F32 or F64 from the other operand -- and so does a CONST naming
   one.  `Math.Sqrt (x)` on an F32 `x` resolves to `SqrtF32`
   (width dispatch: some F32, no F64, twin exists).  Par 2.1;
   tutorial 2; museum `trunc-nan`.

9. **Parameter modes are the borrow checker.**  Value `p: PTR T` is a
   SHARED borrow: readable, NOT writable, and not passable onward as
   VAR.  `VAR` is the mutable handle.  `OWN` moves ownership in.
   `RO` is a read-only borrow -- and on a RECORD it currently COPIES
   (a 160-byte record cost one copy per call in a port; ledgered).
   Par 4.1; probes `write-through-value-ptr`,
   `lend-value-ptr-as-var`.

10. **NEW's first argument says who frees the storage.**  `NEW (pool,
    T, n)` a pool (pool FIRST; a reversed NEW is refused by name);
    `NEW (T)` / `NEW (T, n)` nothing -- the FRAME, and a function
    answering a pointer builds in its caller's arena, so `RETURN t`
    of a frame pointer just works; `NEW (OWN, T)` one owning binding,
    which is DISPOSEd, MOVED by a bare assignment, handed to a THREAD
    or made `SHARED (x)`.  A frame pointer may do none of those and
    may not be stored in a module variable or through a reference
    parameter (refused by name, `frame-ptr-*` probes).  `PTR T IN
    pool` cannot be RETURNed past its pool's frame and cannot be
    DISPOSEd.  A VAR parameter of a pointer-bearing type brings its
    object's pool in with it, so a mutator takes no pool and grows
    its object with `NEW (d, T)`; the pool is named from the ROOT of
    the argument, and an OWN parameter, a value parameter's component
    or a VAR slice as that root is refused (`pool-root-*` probes).  A
    local declared `IN pool` may not hold a frame value
    (`frame-ptr-in-pooled-local`), and a frame value stored into a
    FIELD of a local taints the local, so copying it into a module
    variable is refused (`frame-ptr-record-copy`).  The library is
    migrated: `DynStr.Append (d, s)`, `Time.Iso (t, 0)`, `Plot.Render
    (title, x, y)` take no pool; a constructor that answers `PTR T
    IN pool` (`Csv.Open`, `Frame.New`, `Mat.New`) and a reader that
    answers INTO the caller's pool (`Io.ReadFile`, `Text.Keep`,
    `DynStr.Bytes`) still do -- ask `m9c --json MODULE`.  Par
    4.2-4.3; tutorial 4; probes `pool-escape-on-return`,
    `use-after-move-assign`.

11. **CASE over a CASE RECORD must be total and has no ELSE**; a
    scalar CASE (CHAR, I64) needs one.  The payload is reached ONLY
    through the arm: `CASE v OF | Json.Value.Str (s) : ...`.  Par 8;
    probe `totality-uses-selector-type`; exemplar `corpus/Json.m9`.
    **And a function answers on every path** (checked since
    2026-10-01, par 3 rule 4): one that can reach its END without a
    RETURN or a RAISE is refused at its heading -- an IF with no
    ELSE as the last statement, a WHILE or FOR with nothing after
    it, a CASE arm or a handler that does not answer.  A call is
    never an ending: `Fail (c, msg)` that always raises still needs
    a `RAISE` (or a RETURN) after it.  Probe `function-falls-off-end`;
    tutorial 13, `X13Fall`.

12. **Slices and grids.**  `SLICE (s, start, LEN)` -- start and
    length, never an end.  `LEN (s)`.  `GRID R OF T`: `NEW (pool, T,
    n1, n2, ...)`, `g[i, j]` (every axis, every access checked),
    `LEN (g, axis)`, `VIEW (g, i, ALL)` drops an axis and keeps one.
    Rank is in the TYPE.  Row-major: the innermost loop indexes the
    RIGHTMOST axis, or you pay 5x in cache misses (measured).
    Par 2.2.1; exemplar `corpus/Mat.m9`.

13. **FOR "C" units**: every procedure `[SERIAL]` or `[REENTRANT]`,
    C.* types only in the signature, the C name bound as a string
    literal (`PROCEDURE X = "c_name" (...)`).  `[SERIAL]` means
    SERIALISED -- the generator brackets every call with the unit's
    monitor.  Par 7; exemplar `corpus/Grib.m9`.

14. **Module VARs need `[STATEFUL]` on the definition.**  Prefer a
    record the caller owns: a 43-module port has none.  Probe
    `module-state-without-stateful`; exemplar `corpus/Plot.m9` for
    when state is right.  **A table of literals is a CONST, not a
    module VAR** (from 0.14, par 2.2.4): `CONST Primes = [2, 3, 5]`,
    at module level in the implementation part, literals of ONE type
    (`[1, 2.5]` is refused), then `Primes[i]`, `LEN (Primes)` or the
    whole table to an `RO` parameter -- nothing else may name it
    bare.  A map from NAMED codes to values stays a `CASE`.  Probes
    `aggregate-*`, `const-table-*`; exemplar `corpus/AggUse.m9`.

15. **Concurrency is `THREAD (proc, arg)` with ONE pointer-shaped
    argument, `MONITOR RECORD` with bound procedures, `WAIT`/`SIGNAL`
    inside them.**  Do the work OUTSIDE the bound procedure -- a
    bound body holds the lock.  **A monitor's fields are reachable
    ONLY from a procedure bound to it** (checked since 2026-08-31:
    the binding is the bare FIRST parameter), so do not initialise
    them from the module body -- pool storage and module VARs are
    already zero, and a value read out needs a short bound accessor.
    Par 6; exemplar `runtime/test/serialtest.m9` (the work outside,
    a short bound procedure to record completion).

16. **Known gaps -- route around, do not fight**: nested procedures
    parse but are unsupported (hoist); `F (x).field` does not parse
    (name the intermediate); no conditional compilation (two files,
    one per variant -- `Kind-r4.m9` / `Kind-r8.m9` differing in one
    TYPE -- and the build copies the chosen one into place); a local
    named like a libm function (`cosf`) collides in the emitted C.

17. **What the checker will NOT catch** -- the C compiler or the run
    will: an EXCEPT handler's payload order (`Json.ParseError` takes
    msg FIRST), arithmetic in a transcribed expression whose
    association differs from the original (`a*b**2` is `a*(b*b)`), a
    branch no test enters, and **a CASE-arm binder used at the wrong
    type** -- the binder has no type in the checker, so `k := t` for
    `I64 k` and a STR binder is silent and only the C compiler
    objects.  The one place it DOES complain is `+`: "cannot
    concatenate a string with an unknown type" means the operand is a
    CASE-arm binder, and copying it into a declared local first is
    the workaround.  **And a write through a COPY of read-only
    storage**: from 0.14 a string literal, a `CONST` or an `RO`
    parameter is lent only to an `RO` parameter (par 2.4; probe
    `literal-to-writable-slice`), so write `RO` on every slice or
    STR parameter the procedure does not write -- a by-value one
    handed a literal is refused at the call.  What is NOT followed
    is the copy: `t := s ; t[0] := 'X'` with `s` read-only is
    accepted and, for a literal, dies with SIGSEGV.
